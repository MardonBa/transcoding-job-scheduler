## Local development

Requirements: Docker, Go (version in `backend/go.mod`).

### 1. Environment

```bash
cp .env.example .env
```

Fill in the passwords. `DATABASE_URL` and the MinIO keys are built from the `POSTGRES_*` and `MINIO_ROOT_*` values, so each secret only lives in one place.

Postgres and MinIO only read `POSTGRES_*` / `MINIO_ROOT_*` the first time their volumes are created. If you change them afterwards, recreate the volumes (this deletes all local data):

```bash
docker compose down -v
```

### 2. Backing services

Starts postgres, redis and minio, and creates the `uploads` and `outputs` buckets:

```bash
docker compose up -d
```

Check that postgres, redis and minio show as healthy (`minio-init` runs once and exits):

```bash
docker compose ps -a
```

### 3. Migrations

Migrations live in `backend/migrations/` and run with [goose](https://pressly.github.io/goose/), pinned as a Go tool in `backend/go.mod`. Run from `backend/`, with `.env` loaded into the shell:

```bash
cd backend
set -a; source ../.env; set +a
```

Apply all migrations:

```bash
go tool goose -env=none -dir migrations postgres "$DATABASE_URL" up
```

Show which migrations are applied:

```bash
go tool goose -env=none -dir migrations postgres "$DATABASE_URL" status
```

Roll back the latest migration:

```bash
go tool goose -env=none -dir migrations postgres "$DATABASE_URL" down
```

Create a new migration (sequential numbering):

```bash
go tool goose -dir migrations -s create <name> sql
```

`-env=none` stops goose from looking for its own `.env` in `backend/`, since the shell already has the values.

Once a migration has been applied anywhere other than your machine, don't edit it. Add a new one instead. goose tracks applied versions in `goose_db_version` and won't re-run a changed file.

### Troubleshooting

| Symptom | Cause |
|---|---|
| `password authentication failed` | `DATABASE_URL` doesn't match the credentials the volume was created with. Fix `.env`, then `docker compose down -v` and `up -d` again |
| `role "..." does not exist` on `[::1]:5432` | A Postgres installed on the host (e.g. Homebrew) is also on port 5432. Stop it (`brew services stop postgresql@<version>`) or connect via `127.0.0.1` |
| `database "..." does not exist` | The database name in `DATABASE_URL` doesn't match `POSTGRES_DB` |
